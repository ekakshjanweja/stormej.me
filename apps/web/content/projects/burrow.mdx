my mac holds everything: xcode data, simulators, flutter and bun projects, containers, recordings. i wanted one place to see what's eating the disk, clear it safely, and push the important stuff to the homelab.

## what it does

<Spread label="overview" landscape media={["/images/burrow/overview.webp"]}>

### overview

one headline like "storage is getting full, you can probably clear 32 gb", then numbered suggestions with one action each.

</Spread>

<Spread label="storage + cleanup" landscape media={["/images/burrow/cleanup.webp"]}>

### storage + cleanup

a cached map of downloads, projects, xcode, simulators, caches and containers. cleanup runs through [mole](https://github.com/tw93/mole) and won't run without a fresh preview.

</Spread>

<Spread label="backups" landscape media={["/images/burrow/backups.webp"]}>

### backups

hosts come from `~/.ssh/config`. files go to folders that already exist on the host, and projects stay together. every transfer is staged, sha-256 verified, then moved in without overwriting anything.

</Spread>

### bring back

browse the host, pick files, pull them back with the same hash and stage flow.

<Spread label="system, battery, power" landscape media={["/images/burrow/system.webp"]}>

### system, battery, power

cpu, gpu, memory, thermals, processes grouped by app. bluetooth accessory charge. keep awake, sleep, lock, all native.

</Spread>

### projects, services, containers

dev runtimes and open ports grouped by repo, homebrew services and launch agents, docker and podman with a "what you can clear" section.

<Spread label="aerospace" landscape media={["/images/burrow/aerospace.webp"]}>

### aerospace

one-click tidy for the tiling window manager, plus a config editor that validates and restores itself if the config breaks.

</Spread>

<Spread label="history" landscape media={["/images/burrow/history.webp"]}>

### history

optional 30 days of activity, recorded once a minute, charted over 24 h, 7 d and 30 d.

</Spread>

## barely there

two processes. an appkit menu bar agent is the only thing always running, and the window app quits when you close it.

nothing samples unless a view is watching, commands wait on exit events instead of polling, and the storage map walks with fts(3) in a child process at most once a day.

## advisors

folder routing uses local rules by default, or apple intelligence on device. openrouter, claude code, codex and muse are opt-in and run headless in an empty scratch folder with read-only tools. only file names ever leave the mac, never contents, full paths or host addresses.
